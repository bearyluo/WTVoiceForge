# 战雷声匠（WT Voice Forge）· v1 核心版实施计划

## Context

这是一个要发给战雷社区使用的公开项目，但 v1 只聚焦一件事：**一站式把参考音色做成可用的战雷语音包**。

不先把装包器、市场、云端这些铺开；v1 先把“创建语音包”这条主链路做顺、做自由、做可复用：

- 输入参考音频 → GPT-SoVITS 克隆音色 → 自由选事件和映射 → 批量合成 → FMOD 构建 → 导出语音包；
- 不局限于陆战乘员/空战告警几个预设，任何官方工程里存在的 bank/事件都能选；
- 允许高级用户改素材路径、事件、目标 bank、构建参数和包清单；
- 普通用户用预设也能跑通，不被高级选项淹没。

同时保留这些硬约束：

1. **参考音频导入即可用**：M2 先做零样本克隆，不强迫先训练；多段素材微调放到 M2.1；
2. **文件名不能配错**：每句台词绑定事件 GUID、bank、源素材路径和源文件名；CSV 回填按 `event_id` 精确匹配；
3. **替换范围覆盖** RWR/锁定告警、导弹发射/飞行、击杀/助攻提示、陆战击杀镜头等，而不只是乘员语音。

### 已核实的关键事实

- `aircraft_gui.assets.bank` 内确有 `radar_lock`、`vws_lock`、`vws_missile`、`vws_missile_launch`、`missile_launch`、`enemy_destroyed`、`ui_kill_assist`、失速/迎角告警等事件。
- `aircraft_guns.assets.bank` 内确有 `missile_start_*` 等导弹发射/飞行素材。
- `tanks_effects.assets.bank` 内确有 `killscene_*` 和 `shell_flight` 等陆战击杀镜头/命中素材。
- 官方 FMOD 工程的 `Metadata/Event/*.xml` 记录“事件 → bank GUID”，`Metadata/Bank/*.xml` 记录 bank 名，`Metadata/Asset/*.xml` 记录素材路径，可以自动生成目录，不需要把分类写死。
- 纳西妲包中 `_crew_dialogs_ground_zh.bank` 与英文版字节一致，证明“英文槽位构建 → 改名为目标语种”可行；当前版本的改名实测放到 M3。
- 用户确认采用当前战雷语音包社区常见的 GPT-SoVITS 流水线；RVC 不再作为主引擎。
- GPT-SoVITS v4 Windows 整合包自带 Python、PyTorch、预训练模型和 FunASR，可由应用按需下载；本机 6GB 显存已完成零样本合成实测。

- 云端训练/API、模型市场、账号系统；
- 一键安装所有 AI 组件（运行时按需下载，游戏素材/模型不进包）；

## 2. 高自由度设计（v1 的重点）

1. **数据驱动目录**
   - 从官方 FMOD 工程生成 `catalog.json`：事件名、bank、素材路径、语种、分类、时长、标签；
   - 分类只是“视图”，不是白名单；用户可按 bank、目录、关键字、事件名筛选；
   - 新 bank/事件不需要改代码，重新生成目录即可。

2. **任意事件选择**
   - 支持单选、多选、按分类全选、按搜索结果全选；
   - 显示每个事件属于哪个 bank、是否会连带替换同 bank 的其他事件；
   - 支持“只做测试子集”和“全量”。

3. **自由映射**
   - 把 wav 拖到事件上直接替换；
   - 支持按文件名批量映射（例如 `event_name.wav`）；
   - 支持一个音频映射到多个事件；
   - 支持保留原音、静音、删除三种未映射策略。

4. **按事件/按分类设置**
   - 每个事件或分类可单独设置语速、参考音频/音色、发音语言等；
   - 支持批量应用、复制设置、恢复默认；
   - 高级参数不隐藏，但默认折叠。

5. **自定义分类**
   - 用户可建自己的分类（如“导弹告警”“击杀提示”“我的收藏”），存为 JSON；
   - 分类可导入/导出，便于社区分享制作方案。

6. **高级模式**
   - 手动改素材路径、事件名、目标 bank、输出文件名；
   - 查看/编辑将要执行的 FMOD 构建参数；
   - 编辑导出包清单（名称、作者、版本、语种、说明、预览图）；
   - 导出中间 WAV、映射表、FMOD 工作副本，方便二次加工。

7. **预设但不强制**
   - 内置“陆战乘员”“空战 VWS”“导弹/击杀”“陆战击杀镜头”预设；
   - 预设只是帮你勾选事件和参数，随时可改；
   - 所有预设最终都落到同一套自由映射数据结构。

8. **可恢复**
   - 工程自动保存；训练、转换、构建都可中断续跑；
   - 单条失败可重做；构建失败可回滚到上一版导出。

## 3. 用户流程

### A. 新建工程

选择战雷目录 → 自动找官方 FMOD 工程（或手动选）→ 选目标 bank/分类 → 建工程。

### B. 取素材

解包目标 bank → 目录浏览/试听 → 勾选事件 → 看覆盖率 → 可先做 10 条测试。

### C. 造音色

导入参考音频 → 检查质量 → 轻量/标准训练 → 模型卡片（N 卡 CUDA；A 卡 DML Beta）→ 可断点续训。

### D. 换声与自由映射

批量换声 → A/B 试听 → 拖拽/批量映射 → 单条重做 → 响度统一 → 可导出中间 WAV。

### E. 构建与导出

选目标 bank → 构建 FMOD → 收集 `.assets.bank` + `.bank` → 陆战乘员按目标语种改名 → 生成 `.wtvoice` zip（清单 + bank + 试听 + 说明）。

### F. 高级用户

打开高级模式 → 改路径/事件/bank/参数 → 导出 FMOD 工作副本或映射表 → 自己继续加工。

## 6. 关键技术方案

### 6.1 游戏、工程与 bank

- 用 `aces.exe` + `sound` + `config.blk` 校验战雷根目录；Steam 库读 `libraryfolders.vdf`，独立客户端查常见路径/注册表，最后允许手动选。
- 官方 FMOD 工程（Gaijin 的 `fmod_studio_warthunder_for_modders`）只读；每个工程/构建用独立工作副本，避免污染。
- 语种 bank：`_crew_dialogs_common_<lang>`、`_crew_dialogs_ground_<lang>`。官方工程只有 4 个陆战素材槽位，所以用 `english_us` 构建后改名成目标语种；纳西妲包已验证，M1 再测当前版本。
- 全局 bank：`aircraft_gui`、`aircraft_guns`、`tanks_effects` 等，不按语种分文件，直接替换。
- VWS 三套语音 `betty`/`rita`/`xiao906` 在素材目录里，支持全替换或按套替换。

### 6.2 目录与解包

- 解析官方工程 `Metadata/Event`、`Metadata/Bank`、`Metadata/Asset` 和 `Assets/`，生成 `catalog.json`：
  - 事件名、bank、素材路径、语种、分类、时长、标签；
  - 例：`enemy_destroyed` → `aircraft_gui` → `Assets/gui/enemy_destroyed.wav`。
- 用 `vgmstream-cli -S 0 -o <out>/?n.wav <bank>` 解包，按文件名映射。
- 覆盖率：命中/总数、未命中前 N 条、按分类统计。
- 未命中策略：目标语种原 bank 有同名文件优先；否则保留官方原音；不静默丢文件。

### 6.3 GPT-SoVITS（M2 零样本 / M2.1 微调）

- 运行时：官方 v4 Windows 整合包，自带 `runtime/python.exe`、`api_v2.py` 和预训练模型；只监听 `127.0.0.1`。
- M2 零样本：
  - 参考音频 3–10 秒，参考文字必须与音频内容一致；中文/粤语可用包内 FunASR 自动识别；
  - 请求 `/tts`，`text_split_method=cut5`，输出 32 kHz WAV；
  - 逐句合成，失败只标记该句，不中断整批；结果按台词 ID 保存。
- M2.1 微调（尚未实现）：
  - 数据预处理：切片 → ASR 标注 → `1-get-text.py` → `2-get-hubert-wav32k.py` → `3-get-semantic.py`；
  - 训练 `s2`（SoVITS）与 `s1`（GPT），产出 `SoVITS_weights_v4/*.pth` 和 `GPT_weights_v4/*.ckpt`；
  - 训练完成后调用 `/set_sovits_weights`、`/set_gpt_weights` 切换，并把模型路径写回项目；
  - 进度/取消复用 `jobs.Manager`，训练与构建不同时跑。
- 模型/项目分离：项目只引用模型；换模型不丢台词和事件绑定。

### 6.4 自由映射的数据结构

```json
{
  "project": "my-pack",
  "targets": [
    {
      "event": "enemy_destroyed",
      "bank": "aircraft_gui",
      "asset": "Assets/gui/enemy_destroyed.wav",
      "source": "converted/enemy_destroyed.wav",
      "model": "my-voice",
      "params": { "pitch": 0, "index_rate": 0.75, "protect": 0.33 },
      "mode": "replace"
    },
    {
      "event": "vws_missile",
      "bank": "aircraft_gui",
      "asset": "Assets/vws/betty/vws_missile.wav",
      "source": "converted/vws_missile_betty.wav",
      "mode": "replace"
    }
  ],
  "unmapped": "keep",
  "advanced": {
    "target_bank": "aircraft_gui",
    "build_args": ["-build", "-ignore-warnings"]
  }
}
```

- UI 只是编辑这份 JSON；高级模式可以直接看/改。
- 分类、预设、收藏都是这个结构的视图。
- 导出时可一并导出映射表，方便社区复用。

### 6.5 构建与导出

- `fmodstudiocl.exe -build -ignore-warnings <project>.fspro`；构建前检查工程版本、素材缺失、文件锁、磁盘。
- 收集目标 bank：
  - 陆战：`_crew_dialogs_ground_en_us` + `_crew_dialogs_common_en` → 改名成目标语种；
  - `aircraft_gui` / `aircraft_guns` / `tanks_effects`：直接复制。
- 大 bank（`aircraft_guns` 35MB、`tanks_effects` 29MB）显示阶段进度，允许先做测试子集。
- 导出 `.wtvoice`：
  - `manifest.json`（名称、作者、版本、分类、bank、哈希、游戏版本、说明）；
  - `sound/mod/`（社区可直接解压合并的结构）；
  - `preview/`（试听）；
  - `README.txt`（安装说明）；
  - 映射表（可选）。
- 导出时校验：路径穿越、绝对路径、符号链接、超大文件、哈希。

### 6.6 显存与运行时

| 场景 | 本机实测 / 建议 |
|---|---|
| GPT-SoVITS v4 零样本 | RTX 3060 Laptop 6GB 可用；首次启动 30–90 秒 |
| 多段素材微调 | 6GB 可尝试小 batch；8GB 以上更稳（M2.1 实测后再写死） |
| CPU | 可运行，明显更慢，只作兜底 |

- 合成时关闭游戏，避免显存争用。
- 启动失败时展示 `data/logs/gpt-sovits-api.log` 末尾，不静默失败。
- 训练与 FMOD 构建不同时跑。
- 安装包下载/解压峰值需要约 2 倍包体积的临时空间，开始前检查磁盘。

## 9. 风险与对策

1. **A 卡训练**：GPT-SoVITS 官方以 CUDA 为主；A 卡未实测，M2 只承诺 N 卡零样本，训练不承诺 A 卡。
2. **参考文字对不上**：自动识别只支持中文/粤语 16 位 WAV；其它情况要求手动核对，合成前不隐藏参考文字。
3. **Bank 整体替换**：一个 bank 只能由一个包提供；UI 明确提示同 bank 会连带替换；不做部分覆盖的危险操作。
4. **大 bank 构建慢**：阶段进度、测试子集、缓存、训练/构建不同时跑。
5. **RWR 边界**：没有 `rwr_*` 独立事件；部分提示可能引擎合成；目录标可替换/不可替换，不做虚假承诺。
6. **范围膨胀**：v1 只做创建主链路；装包器、云端、模型市场、微调训练按里程碑后置。
7. **游戏更新**：版本检测、工程更新提示、旧包保留/回滚。

### M3.8 · 多版本候选合成与选用（已完成，2026-10-24）

- 背景：微调后的 GPT-SoVITS 音色可用，但同一句偶尔会有停顿、尾音或语气偏差；用户要求一次生成多个版本，自己挑最合适的。
- 台词表右上角新增“每句版本数”1–4（默认 3），单句与批量合成共用；按钮和提示会随版本数更新。
- 数据层新增 `takes` / `selected_take`：版本音频存 `audio/takes/<line_id>/<take_id>.wav`，最多 4 个；`save_takes`、`select_take`、`find_take`、`clear_all_takes` 管理版本与清理。
- 选中的版本会原子复制回 `audio/<line_id>.wav`，构建、导出和 manifest 继续读原路径，不需要改 FMOD 链路。
- 合成 API 接收 `versions`，每个版本用 `base_seed + variant * 104729` 的不同种子；失败时保留旧音频和旧版本，只记录错误。
- 接口：`GET /api/voice/audio?...&take=` 试听单个版本；`POST /api/voice/take/select` 选用。改文本、重新导入文本、重新训练音色会清空旧候选。
- 修复：上次记住的项目被删除或换了数据目录时，声音目录会一直停在“项目不存在”。现在启动时校验项目是否存在，不存在就回退到第一个可用项目。
- 实测：135 个单元/接口测试通过，覆盖多版本保存、默认选中、切换、越界拒绝、文本变更清理与旧项目兼容。

### M3.9 · 多版本差异与截断保护（已完成，2026-10-24）

- 问题：用户反馈三版“听起来一模一样”。检查确认文件并非字节相同（2.92 / 2.84 / 2.88 秒），但同一参考、同一文本、`top_k=5` 下只换随机种子，GPT-SoVITS 的语气差异小到听不出来。
- 参考轮换：第一版沿用当前参考音频；其余版本从项目里其他有文字的参考录音均匀抽取（v2 项目 48 段中取 039_nav_09 / 007_alive_07 / 023_fox_02），并记录每版 `ref_file`。只导入一段参考时仍重复同一段。
- 采样差异：候选依次使用 `top_k` 5 / 10 / 20 / 30、`temperature` 1.0 / 1.0 / 1.05 / 1.1，避免一味拉高温度造成发音崩坏。
- 截断保护：多版本使用 1.45 倍严格时长下限，短音频自动换种子最多重试 3 次；仍不合格的候选跳过，其余候选照常保存；全部失败才把整句标错并保留旧音频。
- 实测：严格保护前第 3 版只有 1.52 秒，FunASR 只识别出“但是哥哥”，明显截断；加固后第 3 版重试为 2.92 秒，三版都能识别出完整句子，时长 2.92 / 2.08 / 2.92 秒，参考分别为 nav / alive / fox。
- 界面：候选按钮的悬停提示显示所用参考文件；任务结束提示会说明“N 句有候选失败”。
- 测试：138 个单元/接口测试通过，新增参考轮换、`ref_file` 保存、采样参数透传和严格截断拒绝测试。

### M6.5 · 试听定位、继续听与循环（已完成，2026-10-24）

- **背景**：一个 60 多句的语音包连续试听时，听到某句有问题往往已经播到后面；停止后“一键试听全部”又从第一句重来，逐句修音时很难定位和续听。
- **定位**：快速制作和高级编辑的“当前试听”槽显示“第 N/62 句”、事件用途和台词文本；播放中或停止后都可以点“定位当前句”，把对应卡片滚到视野中央并短暂高亮。快速页会先清除搜索词、切回“全部”、展开分页；高级页会取消“只看未完成”筛选。即使原来卡片没渲染，也能自动恢复列表后定位。
- **继续听**：停止时记录当前句（`resumeId`），按钮旁显示“从第 N 句继续”。单句重新生成完成后只试听这一句，播完把续听点设到下一句；全部播完则把续听点设回第一句。高级编辑合成/换声会先停止播放并保留位置，生成后可直接“继续听”。
- **循环**：快速页和高级页各有一个“循环”开关，默认开启并写入 localStorage。开启时播完最后一句自动回到第一句继续，按钮和播放器标签显示“循环”；关闭时播完显示“试听完成（N 句）· 点‘继续听’从头循环”，按钮恢复为可再次播放。
- **失败保护**：连续 3 句音频加载/播放失败会停止队列并提示，避免损坏文件导致跳过/循环空转；单句失败仍先提示并跳到下一句。
- **验证**：用真实 62 句项目在无头 Edge 中注入确定性的 `ended` 事件（不依赖音频时长）实测：循环从 62/62 回到 1/62，关闭循环后停在第 62 句并显示“试听完成”，继续听从第 9 句暂停处接着播或从第 1 句重播；单句重生成播完提示“从第 5 句继续”；定位会清除筛选并滚到卡片（top 145/bottom 343，视口 488）。212 个单元/接口测试通过。
- **边界**：定位是手动动作，不恢复列表自动滚动，避免重新引入 M6.3 的“界面跟着滑动”；续听位置按播放队列（已合成且非音效行）计算，删除/重新准备台词后会回退到第一句。
