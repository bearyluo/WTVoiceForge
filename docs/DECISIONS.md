# 产品决策记录

日期：2026-10-23
项目：战雷声匠 / WT Voice Forge

这份文档把这次聊天里确认的事情固定下来，避免后续开发时反复摇摆。原始聊天记录在 `docs/chat/`，只作本地留档，不进入公开仓库。

## 1. 项目定位

- 面向战雷玩家社区公开分享的工具，不是个人一次性脚本。
- 必须具备普遍性：任意战雷安装路径、不同游戏版本、不同显卡、不同语言。
- v1 只聚焦“一站式制作语音包”，不先铺装包器、市场、云端。

## 2. v1 主链路

```text
参考音频 → RVC 训练/换声 → 选事件与自由映射 → 批量转换 → FMOD 构建 → 导出 .wtvoice
```

必须做到：

- 任意官方工程里存在的 bank / 事件都能选，不限于固定分类；
- 拖拽映射、按文件名批量映射、单条覆盖、保留原音/静音；
- 每个事件或分类可单独设置模型和参数；
- 自定义分类、预设、收藏，存为 JSON，可导入/导出；
- 高级模式可改素材路径、事件名、目标 bank、构建参数、包清单；
- 训练、转换、构建都可中断续跑；
- 导出包带清单、哈希、试听和安装说明。

## 3. 音效覆盖

首版必须覆盖：

| 分类 | 目标 bank | 代表事件/素材 |
|---|---|---|
| 陆战乘员语音 | `_crew_dialogs_common_*`、`_crew_dialogs_ground_*` | 乘员报点、装填、击杀确认 |
| 空战 VWS / 告警 | `aircraft_gui` | `vws_lock`、`vws_missile`、`vws_missile_launch`、`radar_lock`、`missile_launch`、失速/迎角告警 |
| 击杀/助攻提示 | `aircraft_gui` | `enemy_destroyed`、`ui_kill_assist` |
| 导弹发射/飞行 | `aircraft_guns` | `missile_start_*`、`rocket_fly_by`、`missile_sonic_boom` |
| 陆战击杀镜头/命中 | `tanks_effects` | `killscene_*`、`shell_flight` |

注意：

- FMOD bank 是整体替换；一个包替换 `aircraft_gui` 会连带替换该 bank 的其他事件。
- 没有找到 `rwr_*` 独立事件名；部分 RWR 提示可能由引擎合成。首版只承诺官方工程里实际存在、可构建的事件，不做虚假覆盖。
- 陆战乘员 bank 用英文槽位构建后改名成目标语种；纳西妲包已验证，M1 在当前版本再测。
- VWS 三套语音 `betty` / `rita` / `xiao906` 在素材目录里，支持全替换或按套替换。

## 4. 硬件策略

| 场景 | NVIDIA | AMD |
|---|---|---|
| 只装包/试听 | 任意 | 任意 |
| 换声 32k | 2GB 起 | 4GB 起（DirectML） |
| 轻量训练 32k/batch1~2 | 4GB 起 | 6GB 起（Beta） |
| 标准训练 40k/batch2~4 | 6GB 起 | 8GB 起 |
| 推荐 | 6GB | 8GB |

- N 卡走 CUDA，fp16；A 卡走 DirectML，fp32。
- 4GB 档强制 32k、batch 1~2、短切片、关闭 GPU 数据缓存。
- A 卡训练：官方 RVC 训练循环仍以 CUDA 为主，需要补丁桥接；v1 标 Beta，6GB 起，至少一张 RX 6000/7000 实机验收。4GB A 卡只保证换声。
- GPT-SoVITS 在 v1 不做；后续 A 卡默认 CPU，N 卡 CUDA。

## 5. 技术路线

- 基于“战雷圆桌工程”（MIT）的游戏路径、解包、FMOD 构建思路二次开发，保留 LICENSE/NOTICE。
- 使用 Gaijin 官方 FMOD 工程作为素材/事件/bank 的权威来源；不随项目分发。
- 用 vgmstream 解包 bank（ISC，后续随包分发）。
- 用官方工程 `Metadata/Event`、`Metadata/Bank`、`Metadata/Asset` 自动生成目录，不把分类写死。
- 用 `fmodstudiocl.exe -build -ignore-warnings <fspro>` 构建。
- 陆战 bank：英文槽位构建 → 改名成目标语种。
- 全局 bank：直接替换，不改名。

## 8. 安装即用的实现取舍

- 不把 RVC 的 5~7GB 整合包塞进 exe，也不自行重新打包。exe 只有约 12MB；首次需要 AI 时再下载。
- 直接使用 RVC 官方整合包（自带 Python、PyTorch、FFmpeg、预训练模型），比让用户自己装 Python/CUDA/torch 更可靠。
- RVC 整合包来源固定为 Hugging Face `lj1995/VoiceConversionWebUI`；每个包记录字节数和 SHA-256。优先官方源，失败时回退 `hf-mirror.com`，两边都校验同一个哈希。
- 下载目录、安装目录用户可选；默认在 exe 同目录 `data/components`，本机开发配置放在 `D:\WTVoiceForge\components`。
- 下载与解压峰值需要约 2.5 倍包体积的临时空间；开始前检查磁盘，不足直接拒绝。
- RVC 目录识别兼容源码版与整合包：`webui.py` / `infer-web.py` / `go-webui.bat` 加上 `configs`、`assets` 等目录即可；选择父目录时会向下找一层。
- 解压优先用 7-Zip；没有时使用 Windows 10/11 自带的 `tar.exe`（bsdtar 支持 7z）。
- 打包后的程序是本地服务 + 桌面控制窗口，工作台仍在浏览器里；后续若需要真正的单窗口体验，再评估 WebView2。

## 10. M1 目录与解包（2026-10-23）

- **目录数据源**：只解析官方 FMOD 工程的 `Metadata/Bank`、`Metadata/Event`、`Metadata/AudioFile` 和 `Assets`；不把分类、事件或 bank 写死。
- **事件 → 素材**：Event XML 里的 `audioFile` GUID 指向 `Metadata/AudioFile` 的 `assetPath`；不能只靠 SingleSound 的 name，因为大量 SingleSound 没有 name。
- **性能**：12,256 个事件顺序解析约 5–7 秒；34,789 个 AudioFile 元数据用 8 线程读取，约 5–10 秒（串行实测 4 分钟，已改并行）；Assets 文件名索引约 1 秒。
- **缓存**：`<data_dir>/cache/catalog/catalog.json`，schema 2，原子写入；指纹包含 kit 路径、fspro 大小/mtime、Bank/Event/AudioFile 数量与目录 mtime、Assets 文件数。指纹不匹配仍允许浏览旧缓存并提示；kit 路径不同则视为不可用，避免用旧工程路径试听新工程。
- **缺失素材**：官方工程只带英语/俄语无线电源文件。目录仍如实标记 `exists:false`，不丢弃；另提供 `tools/fill_radio_chat.py`，按“流名 + 元数据时长”从游戏 `dialogs_chat_*` bank 精确补全其余语种，M1 实测补入 15,268 个文件（含 `hchn` 从 `chn` 复制，二者 935 条元数据时长逐条完全一致），缺失从 15,316 降到 48。剩余 48 个是非语音效果/提示音，游戏 bank 无同名流，继续如实标记。补全脚本只读游戏目录，提取出的音频不随项目分发。
- **试听**：源素材扩展名是 `.wav`，实际多为 Ogg Vorbis，按文件魔数返回 `audio/ogg` / `audio/wav`；支持单段 HTTP Range 和 HEAD，便于拖动进度。
- **vgmstream**：固定官方 r2117 win64，4,468,180 字节，SHA-256 `6c4a8a3813864fefed081bbd337dbc0ad93bf88e0b92f5db98d7ab258b22dc6c`；优先用随 exe 内置的 `vendor/vgmstream`，源码模式缺失时自动下载到数据目录。只用 Python `zipfile` 安全解压，拒绝绝对路径、`..` 和符号链接。
- **解包命名**：实测 `?n` 会因重名只剩 226/324 个文件，因此使用 `?s_?n.wav`，完整保留 324 个流；产物是标准 RIFF WAV。
- **解包写入**：只读游戏 `sound`；输出先写 `<data>/unpacked/.tmp-*`，整理后再原子替换 `<data>/unpacked/<bank>`，取消/失败保留旧结果并清理临时目录。
- **匹配口径**：目录覆盖率是权威数据；“解包匹配”是 best-effort，仅用于核对内部流名，不参与覆盖率计算。
- **范围边界**：中文乘员 bank 改名实测需要真实 FMOD 构建，移到 M3；M1 不写游戏目录、不下载 5.6GB RVC 运行时。
- **任务模型**：目录生成与解包共用一个单活动任务管理器，进度/取消通过 `/api/jobs/current` 轮询；组件下载保留独立管理器，暂不强行合并。

## 11. M2 声音项目与 GPT-SoVITS（2026-10-23）

- **主引擎换成 GPT-SoVITS**：用户确认采用当前战雷语音包社区常见的 GPT-SoVITS 流水线，RVC 不再是主流程。保留 `app/engines/rvc.py` 只做旧目录检测/配置兼容，不再提供 RVC 安装入口。
- **先零样本、后微调**：M2 用“参考音频 + 参考文字”直接克隆，导入即可合成；不把零样本在 UI 写成“已训练”。多段素材微调（1-get-text / 2-get-hubert / 3-get-semantic / s1 / s2 + 权重切换）列为 M2.1。
- **运行时来源固定**：Hugging Face `lj1995/GPT-SoVITS-windows-package` 的 `GPT-SoVITS-v4-20250529.7z`，7,493,794,100 字节，SHA-256 `6461419c7c81f7c23a08e467c040eb25197bf8291ec1107e0104c46354b77146`，已本机核对；解压约 13.4 GB。只调用包内 `runtime/python.exe api_v2.py`，不改包内容。
- **合成接口**：本机随机端口启动 `api_v2.py`，POST `/tts`；参考音频 3–10 秒（短于 3 秒会被上游拒绝），`text_split_method=cut5`，`media_type=wav`，`streaming_mode=false`。12 字中文实测输出约 2–5.4 秒 WAV。
- **随机种子保护**：上游 `seed=-1` 会随机早停（同一句 12 字出现过 0.76/0.8/0.92 秒），换成按“台词 + 参考文字”计算的固定种子后稳定输出；如果输出短于按字数估算的下限，自动换种子重试最多 3 次。同一句重复合成时长一致。
- **参考文字自动识别**：整合包自带 FunASR 中文/粤语模型。上游 `only_asr` 的 VAD 路径对游戏 WAV 返回空结果，改为禁用 VAD 直接调用 paraformer；FunASR 只吃 16 kHz 单声道，应用用标准库做线性重采样，避免额外依赖。自动识别目前只支持 16 位 PCM WAV，其它格式要求手动填文字。
- **精确映射是第一优先级**：每句台词存 `event_id`、事件名、bank、源素材路径、源文件名、全部素材 GUID、`target_file`。同一 `event_id` 不能重复加入（防止一句原文被两条译文覆盖）。
- **CSV 对照表**：导出列 `event_id,event,bank,source_file,source_path,text,status`，带 UTF-8 BOM。导入优先按 `event_id` 精确匹配；没有 `event_id` 时只接受唯一的 `source_file`；`source_file` 与已绑定源文件不一致直接拒绝该行并报错。手动台词没有事件绑定，不参与精确匹配。
- **项目存储**：`<data>/voice_projects/<id>/project.json`、`reference/`、`audio/<line_id>.wav`；合成结果按台词 ID 保存，改文本时清空旧音频，避免“新文字配旧语音”。
- **本地边界**：GPT-SoVITS 只监听 `127.0.0.1`；不上传参考音频、台词或游戏素材；不做遥测。
- **实测**：M2 本机全流程（建项目 → 导入参考音频 → 自动识别 → 精确添加 `enemy_destroyed` → 合成 → 试听）通过；87 个测试通过；游戏目录只读。

## 12. M2.1 微调训练（2026-10-23）

- **训练入口**：声音项目至少 3 段参考音频、总时长 8 秒以上才能点“训练专属音色”；训练前会清空该项目已合成音频，避免旧音色残留。
- **逐条文字**：项目新增 `reference.texts`，按参考音频文件名保存。中文/粤语空缺文字用整合包 FunASR 一次批量识别；其它语言必须手动填写，否则拒绝训练并列出缺文字的音频。
- **数据准备**：用包内 `ffmpeg.exe` 统一转 32 kHz 单声道训练音频和 16 kHz 识别音频；训练名单格式 `wav|speaker0|ZH|text`。音频重命名为 `0001.wav…`，避免中文/空格路径影响训练脚本。
- **脚本调用**：整合包内置 Python 有 `python39._pth` 路径隔离，`PYTHONPATH` 和旧 `users.pth` 不可靠；应用用 `runpy` 引导并显式把包根、`GPT_SoVITS`、`tools` 等加入 `sys.path`，不改包内文件。
- **预处理**：依次跑 `1-get-text.py`、`2-get-hubert-wav32k.py`、`3-get-semantic.py`，然后把 `2-name2text-*.txt`、`6-name2semantic-*.tsv` 合并成训练脚本要求的单文件。上游 `g2pw` 在 onnxruntime 1.19 会打印 `preload_dlls` 异常，但被上游 try/except 捕获，不影响训练。
- **训练参数**：v4 LoRA，s2 2 轮、s1 8 轮、batch 1、`grad_ckpt=True`、LoRA rank 32；6 GB 显存实测约 4.9 GB 占用。
- **权重落盘**：训练结束只保留最终 s2/s1 权重，复制到项目 `train/model/`，删除包内临时权重和训练 checkpoint；重装运行时不会丢模型。项目记录 `mode/state/sovits_path/gpt_path/exp/trained_at`。
- **模型切换**：合成前按项目 `model` 自动切权重；微调项目用项目权重，零样本项目切回 v4 底模。找不到训练权重会明确报错，不静默回退。UI 提供“换回零样本 / 使用训练模型”。
- **实测**：6 段中文无线电、23.5 秒素材，训练 8 分 19 秒；训练后 12 字合成 3.48 秒；切回零样本项目合成 4.08 秒，互不串音色。87 个测试通过。

## 13. M3 FMOD 构建与 `.wtvoice`（2026-10-23）

- **只构建目标 bank**：按台词绑定的 `source.bank` 汇总目标 bank，调用 `fmodstudiocl.exe -build -banks <目标> -platforms Desktop -shared-audio-source-dir <staged> -ignore-warnings sounds.fspro`；不构建、不替换 `masterbank`。
- **工程只读**：官方工程只读；首次构建把 `sounds.fspro`、`Metadata`（约 230 MB）、`Mixing Desk`、`Scripts` 复制到项目 `build/base/`，后续复用。项目 `build/` 可随时删除重建。
- **素材暂存与替换**：只从官方工程 `Assets` 硬链接/复制目标 bank 和 `masterbank` 事件引用的素材到 `build/assets`，再按每句 `source.path` 覆盖为合成 WAV。这样不复制 2.6 GB 全量素材，也不会动官方源文件。
- **成功判定看产物**：FMOD 会顺带检查 `masterbank`；局部素材暂存时它可能报 “required file not found”，但目标 bank 仍正常产出。应用不再用进程退出码判死，而是逐个检查目标 `<bank>.bank` 是否实际生成；缺失才报错。日志保留最后 20 行用于排查。
- **精确映射**：同一个素材路径被两句不同台词引用时直接拒绝构建，避免后写的音频覆盖前一句；未绑定 bank 的已合成台词跳过，并在结果里计数。
- **包格式**：`.wtvoice` 是 zip（store，不再压缩 bank），包含 `manifest.json`（schema 1、目标 bank、逐句 `event_id/event/bank/source_file/target_file/text/audio`、安装目标、可选 config 要求）、`README.txt`、`sound/mod/*.bank`。M3.3 起改为 `sound/mod/` 社区结构，解压后可直接合并到游戏目录；旧 `banks/*.bank` 包仍兼容。`masterbank` 不进包。
- **安装边界**：复制到 `sound/mod/` 并启用 `enable_mod:b=yes`；一个 bank 只能由一个包提供，安装新包会整体替换该 bank。M3 时未做自动写 `config.blk`；M3.2 改为独立安装页，只有在用户勾选时才改并先备份（见 §15）。
- **实测**：`aircraft_gui` 单句构建，317 条流完整保留，`enemy_destroyed` 从原长度替换为 1.000 秒（工程编码为 8 kHz 单声道）；包体 3.69 MB；缓存后构建耗时 96 秒。96 个测试通过。

## 14. M3.1 其他国家语音表汉化（2026-10-24）

- **AudioTable bank**：官方工程里的 `_crew_dialogs_ground_en_us` 等 bank 不是事件 bank；Bank XML 的 AudioTable `sourceDirectory` 指向整棵素材目录，FMOD 会按流名打包。界面只列出这些带 AudioTable 且源目录存在的 bank（实测 14 张）。
- **按流名精确绑定**：每条本地化台词用 `at:<bank>:<流名>` 作为唯一 ID，`source.assets` 保存该名字对应的所有文件路径（高/中距离变体），`target_file` 仍是 `<流名>.wav`。同一流名不会因为同名被写成两句。
- **游戏 bank 为主、工程为辅**：行数取 `game/sound/<bank>.assets.bank` 的实际流名（vgmstream `-m` 只读元数据）；工程里有的文件优先用工程原音，工程缺的流从同语言其他工程目录找备用原音，再缺就从游戏 bank 提取。实测美军陆战 628 个流名，其中 32 条工程没有；游戏中文表 655 个流名，同名复制 623 条，只剩 5 条美军新增行。并集构建后 1272 条流 / 636 个唯一流名。
- **构建细节**：AudioTable bank 不读取 `-shared-audio-source-dir`，必须把素材放到工程缓存自己的 `base/Assets/`；构建前用硬链接镜像已替换的整棵源目录。从游戏 bank 补原音时一次解出整张 bank 再按流序号取文件（实测 5 秒解 1256 条，避免逐条启动 vgmstream）。
- **优先复用游戏中文原音**：“用游戏中文原音补齐”会从 `game/sound/_crew_dialogs_*_zh.assets.bank` 按同名流提取官方中文 WAV，直接作为台词音频（`audio_source=official_cn`），不需要重新合成。实测美军陆战 628 条里 623 条命中，剩余 5 条正是美军比中文多出来的行，才需要翻译。
- **中文项目补齐**：按 `target_file` / 源文件名 / 事件名归一化匹配，把另一个项目的中文文本和已合成音频复制过来；只填空缺，不覆盖已有内容。匹配不到的行标“待翻译”，可试听原音后逐条翻译。
- **UI**：声音目录新增“其他国家语音汉化”卡片，显示游戏流名数、工程新增流数，支持整表加入、中文项目补齐、只看待翻译；台词卡新增“原音”按钮。
- **边界**：中文工程没有 AudioTable 源目录，所以汉化以其他语言 bank 为底；本地化 bank 会重新编码，包体大小与游戏原 bank 不完全一致；游戏内实听仍待完成。
- **实测**：美军陆战单句验证构建成功（`.assets.bank` 12.5 MB，替换流 1.000 秒）；完整 623 句官方中文复用构建包体 14.8 MB / `.assets.bank` 14.57 MB，1272 条流 / 636 个唯一流名，316 秒；104 个测试通过。

## 15. M3.2 独立的语音包安装器（2026-10-24）

- **输出与替换分离**：构建/导出只产出 `.wtvoice`；导入、解析、安装、卸载和还原是新的 `#packs` 页面与 `/api/packs/*` 接口，不复用构建页按钮，避免“导出即替换”的误解。
- **包输入**：`.wtvoice`、含 `.bank` 的普通 zip、单个 `.bank`。只读取 `manifest.json` 和 bank；拒绝超过 1 GB、超过 5000 个条目、解压后超过 1.5 GB、加密条目、绝对路径/`..` 路径、重名 bank、`masterbank.bank` / `masterbank.strings.bank`。包内其他文件（README 等）不落盘、不执行。
- **原始上传**：现有 JSON API 限制 1 MB；`/api/packs/upload?filename=` 单独按 `Content-Length` 直接收原始字节，上限 1 GB，落盘后再解析和计算 SHA-256。前端用 XHR 显示上传百分比。
- **安装范围**：只写 `<游戏>/sound/mod`，从不写 `sound` 根目录、游戏本体或官方工程。每个目标 bank 先写临时文件、校验 SHA 后再原子替换；任何一步失败按记录回滚。
- **备份**：覆盖 `sound/mod` 同名 bank 前，旧文件复制到 `<数据目录>/packs/backups/<时间>_<上传编号>/banks/`；安装记录写在 `packs/installed.json`，包含每个 bank 的 SHA-256 与备份相对路径。
- **enable_mod**：默认勾选，但只有用户明确勾选才修改 `config.blk`；修改前把原文件备份到同一备份目录。已检测到 `enable_mod` 不存在时插入 `sound{}` 段。游戏运行时拒绝改。
- **进程保护**：安装、卸载、改 `enable_mod` 前用 `tasklist` 检查 `aces.exe`，运行中直接拒绝，避免文件占用和改动不生效。
- **卸载规则**：只删除当前 SHA 仍等于安装记录的本工具 bank；被其他包或手动改过的 bank 跳过并计数。有备份的按备份还原；`sound/mod` 里的第三方 bank 只列出、不删除。
- **覆盖顺序**：`installed.json` 的 `bank_owner` 记录每个 bank 当前由哪个安装记录提供，每条安装记录保存 `previous_owner`。A 的 bank 被 B 覆盖时，必须先卸载 B；卸载 B 会把 bank 文件、备份和所有权还原给 A，再卸 A 才能回到原始状态，避免先卸旧包丢掉原始备份。
- **重装同一个包**：同一个上传编号再次安装时替换旧记录而不是追加；若目标 bank 仍是本工具写入的版本，沿用最初的备份，不会把已安装版本误当“原文件”备份。
- **冲突展示**：解析后逐 bank 显示“新增”“覆盖同名（先备份）”“mod 中已是同一文件”，有 manifest 时预览前几条事件/台词；安装前对覆盖项做二次确认。
- **实测**：用假战雷目录拖入含 2 个 bank 的 `.wtvoice`，解析、安装（写入 `sound/mod` 并开启 `enable_mod`）、安装列表 SHA 校验、卸载移除并清空记录、放弃解析均通过；M3.2 阶段 118 个测试通过。

## 16. M3.3 按官方社区步骤完善安装器（2026-10-24）

- **对齐一手步骤**：官方 wiki 的 Sound modifications 明确：下载模组 → 在 `config.blk` 的 `sound{}` 加 `enable_mod:b=yes` → 在 `sound/` 下创建 `mod` → 解压模组文件 → 启动游戏；还原时把 `enable_mod` 改为 no 并删除 mod 文件。官方 FMOD 工程 Readme 明确：用当前 FMOD Studio 打开官方工程、不要改事件名/路径/mixer 结构、构建改动事件所在 bank。应用只把检查、备份、写入整合，不另立流程。
- **`sound/mod` 包结构**：导出 `.wtvoice` 内部改为 `sound/mod/<bank>`，与社区解压合并方式一致；安装器仍接受旧 `banks/`、`mod/`、根目录 bank、多层目录等历史/社区布局，统一安装到 `sound/mod`。
- **config 开关**：官方必需 `enable_mod`；社区常用 `fmod_sound_enable`；枪炮包可能要求 `useLoopsForGunSound` / `useLoopsForGMGunSound`。安装页按当前 config 状态显示勾选，默认写 enable_mod + fmod_sound_enable，loop 开关默认不写，只有勾选才写。所有改动集中一次备份 `config.blk`，不覆盖用户其他字段。
- **包安全检查**：识别 `.bank` / `.assets.bank` 是否成对，缺少一侧只警告不拒绝（可能是有意只替换音频）；忽略并提示包内可执行文件；RAR/7z 提示先解压；继续拒绝 masterbank 核心 bank、加密/越界/重名/超大包。
- **游戏更新诊断**：社区经验是游戏更新后 `sound/mod` 里的旧 bank 仍会盖住新版同名文件。应用比较游戏原版 `<bank>` 与 mod 文件的 mtime，标记“游戏已更新，建议重装”；该检查只在加载列表时做，不改文件。
- **社区已知风险**：`sound/mod` 里的 `masterbank.bank` / `masterbank.assets.bank` / `masterbank.strings.bank` 和旧 `hangar.bank` 会导致无声、爆音或卡顿，应用只提示，不自动删除第三方文件。
- **进游戏确认**：安装页给出“左上角已启用自定义音效 / 成员组语言 / 枪炮循环开关 / 大更新后重装”清单；成员组语言选项来自社区语音包作者说明，不是所有包都需要。
- **FMOD 版本**：官方仓库当前标注 2.02.22；本机检测到 2.02.28。构建页显示版本差异提示，但同属 2.02 不直接阻止构建；真实游戏内加载仍未验证，若 bank 不加载应换用官方标注版本。
- **实测**：社区 `sound/mod` zip（含 manifest、2 个成对 bank、README 和一个 exe）解析出结构、成对与忽略警告；安装写入 `enable_mod` / `fmod_sound_enable` / `useLoopsForGunSound` 并备份；游戏原版 mtime 更新后列表标记 stale；手工放入 masterbank/hangar 后出现风险提示；卸载回滚正常。合计 121 个测试通过。

## 22. M3.8 多版本候选合成（2026-10-24）

- **问题**：GPT-SoVITS 微调音色已经可用，但同一句仍有随机性；只给一条结果时用户只能反复重合成，且新结果会覆盖上一条，无法 A/B 对比。
- **存储**：每句新增 `takes` 列表和 `selected_take`；版本音频放 `audio/takes/<line_id>/<take_id>.wav`，版本 ID 为 `t_` + 12 位十六进制，单句最多 4 版。主音频 `audio/<line_id>.wav` 继续保留，作为“当前选用版本”的副本。
- **为什么复制回主路径**：构建、导出和 manifest 已经统一读 `line_audio_path`；选用时把版本原子复制回主路径，FMOD 链路零改动，也不会把 take 概念泄漏到语音包格式里。旧项目没有 `takes` 时行为完全不变。
- **种子**：基础种子仍是 `CRC32(台词 + 参考文字)`，第 N 版加 `N * 104729` 后取 31 位；既保持可复现，又让各版真正不同。合成服务内部仍保留短音频换种重试，因此单个版本也可能用掉多个内部种子。
- **交互**：台词表右上角选择 1–4 版（默认 3），单句合成也遵守该设置；只有 2 版以上才显示“候选版本”行。点版本试听 `?take=`，点“选用”调用切换接口，当前版本高亮。合成结束提示选用，不默认替用户挑最佳。
- **清理边界**：改台词、重新导入文本、重新训练音色都会清空旧版本；训练后模型变了，旧版本不再有比较意义。合成失败保留旧音频和旧版本，只把错误写回该行。
- **错误处理**：版本 ID 必须匹配 `t_[0-9a-f]{12}`，试听接口同时校验版本属于该台词且文件存在；非法或过期版本返回 400，不返回任意路径。
- **实测**：135 个单元/接口测试通过，覆盖保存两版、默认选中、切换后主音频时长变化、非法版本拒绝、文本变更清理和批量清理。0.5.8 绿色版在 v2 项目实测 3 版（2.92 / 2.84 / 2.88 秒），试听返回 `audio/wav`；选用第 2 版后主音频与 `t_8518519e7954.wav` 的 SHA-256 一致，页面时长和当前标记同步。
- **启动回退**：修掉“localStorage 里记住的项目被删除/换数据目录后一直显示项目不存在”的问题；`loadProjects` 现在只在项目列表中查找记住的 ID，找不到就回退到第一个项目，不再请求已失效的 ID。

## 23. M3.9 多版本为什么一样，以及怎么改（2026-10-24）

- **诊断**：三版 WAV 的 SHA-256 和时长都不同（2.92 / 2.84 / 2.88 秒），并非复制同一文件；问题在于 GPT-SoVITS 默认 `top_k=5`，同一参考、同一文本下只换种子，韵律差异很小，人耳会当成同一版。
- **主差异来自参考录音**：GPT-SoVITS 的参考音频会强烈影响停顿和语气，仅改采样参数不够。`voice.reference_choices()` 让第一版保持当前参考，其余版本从“有逐段文字”的参考音频里按 `round(len/versions)` 步长取样；v2 项目实际抽到 nav / alive / fox 三段。每版把 `ref_file` 写进 take，界面悬停可查。
- **采样作为辅助**：候选按 `top_k` 5 / 10 / 20 / 30 和 `temperature` 1.0–1.1 递进，既能拉开差异，又避免高随机度把中文发音带坏。第一版保持原参数，老用户的最优基线不变。
- **截断必须拦**：多版本实测出现过 1.52 秒的“第 3 版”，FunASR 只听到“但是哥哥”；说明原来的 0.11 秒/字下限只能挡住严重提前结束。多版本改用 1.45 倍严格下限，并在 3 次重试仍不达标时抛错跳过该候选；其余候选继续保存，只有全部失败才标整句错误并保留旧音频。
- **部分成功策略**：单个候选失败不拖垮整句；任务结果新增 `partial_errors`，提示“N 句有候选失败”，避免把“有 2 版可用”误报成整句失败。
- **实测**：v2 项目同一句三版 2.92 / 2.08 / 2.92 秒，参考分别 nav_09 / alive_07 / fox_02，FunASR 均能识别出完整句子；截断的 1.52 秒版本被严格保护拦下并重试。138 个测试通过。

## 24. M4.0 快速制作：统一音色、国家映射与本地听写（2026-10-24）

- **为什么再加一个页面**：原来的“声音目录”以事件/bank 为单位，适合做精确替换，但普通用户要先理解 14 张 AudioTable、事件绑定和逐句文本。快速制作把页面按任务拆成四步，默认动作是“整张表加入 + 填文本 + 一键合成”，复杂操作仍回“高级编辑”，不删除任何旧能力。
- **配音方式**：包内所有台词统一用用户训练的音色重新合成，不混用官方中文原音。这样换音色后整包听感一致；官方中文原音只用于“听写文本”和“补缺参考”，不进入成品音频。
- **国家映射**：先选阵营，再映射到语言/语音表。德国=de、苏联=ru、英国=en、美国=en_us；美国通用/空勤没有独立表，和英国共用 `_crew_dialogs_common_en`，选择时去重，陆战用 `_crew_dialogs_ground_en_us`。一个 `.wtvoice` 可以包含多张 bank，构建器已支持。
- **通用/空战/陆战拆分**：通用表 `_crew_dialogs_common_*` 同时包含共享乘员无线电和空勤专用台词，无法按 bank 直接分开。快速制作改为行级范围：共享无线电（收到/拒绝/感谢/装填/维修/攻击防守等）归“通用”；降落、航向、高度、返航、掩护、六点、空侦/空援、敌基地空袭，以及 `base_*`/`pilot_*`/`mission_complete_*` 归“空战/其他”；地面表归“陆战”。`base_player_inZone_ground` 归陆战，`base_player_inZone_leave` 归通用；`voice_message_driver_running_gear_damaged` 是地面车辆行动装置受损，仍归通用，不是飞机起落架告警。前端三个复选框分别控制，后端用 `line_scopes` 过滤行；构建时仍写同一张 common bank，未勾选的行保留游戏原音。国家快捷卡片会按当前勾选显示“通用 / 空战/其他 / 陆战”，不再固定写“通用/空勤”。
- **文本来源**：用户选择“官方音频自动听写”。官方中文表只有音频，首次准备用本机 FunASR 批量听写；结果只缓存到 `data/cache/quick/chinese_text_catalog.json`，不放进 exe。听写结果标注“自动听写，可能有错字”，重点类别优先展示，允许用户只改在意的句子。
- **为什么不在 exe 里带听写 JSON**：它来自游戏官方音频，属于游戏素材的衍生内容，不应随公开应用重新分发；同时不同用户的游戏版本可能更新。缓存放数据目录，既能保留首次成本，也避免分发版权内容。随包只带手工整理的缺口译法和占位音译法。
- **占位音处理**：`voice_message_attention_to_point_*` 的 12 个中文流实测是字节相同的 1.5 秒 700 Hz 提示音，不是人声，不能强行听写；标记为“提示音/非语音，保留原音”。后续全量核对 54 张空战/陆战表发现，只有中文、法文、越南文的 common 表是这 12 条同一段占位音；英文、德文、俄文等 14 种语言的同名流是 12 条不同的真人语音，必须结合 bank 判断，不能只看流名统一跳过。陆战 13 条 `driver/gunner ... damaged/repaired` 的中文流是 0.1 秒空占位，按事件名补“占位音译文”（如“驾驶操控受损”），明确标注“官方中文表里是 0.1 秒占位音”，不冒充听写。
- **相同文本去重**：快速包常有几十条相同台词（“收到/干得好/进攻A点”）。合成 API 的 `dedupe=true` 在 1 版模式下按文本分组，每组只跑一次 GPT-SoVITS，再把生成的 take 复制给组内其他台词；每句仍有自己的 take/main audio，构建和高级编辑行为不变。进度按去重后的组数显示，结果返回 `unique_texts`。
- **一次构建多张 bank**：prepare 只准备项目和文本；合成继续走原 `/api/voice/synthesize`，构建继续走原 `/api/voice/build`，快速页只是编排。这样 5 张 bank 的包使用同一套 FMOD 构建和 `.wtvoice` 格式，避免出现第二套导出链路。
- **试听**：训练完成后可以先用 `/api/voice/preview` 生成一条试听（缓存最近 50 个），不必先建包；确认音色后再进入国家选择。
- **实测边界**：5 张表 3422 句、文本缺失 0；6 句跨 5 bank 构建成功。整包全量合成仍可能 45 分钟量级，先小范围验证音色和文本，再跑全量；真实游戏内加载/实听尚未完成。

## 25. M4.1 声音不满意的排查顺序与默认值回退（2026-10-24）

- **用户反馈**：重新生成的 3 版比原先更差，要求“保持默认”。原先默认 3 版，且 M3.9 的多版本会轮换参考录音、把 `top_k` 提到 20/30、温度提到 1.05/1.1；这会把另一段情绪/录音条件的参考带进候选，音色和发音容易漂移。
- **回退**：高级编辑默认 1 版；旧的 `wt.voice.takes` 本地记忆不再读取（新键 `wt.voice.takes.v2`），避免升级后仍自动 3 版。多版本保留，但改为同一参考 + 官方默认采样（`top_k=5`、`top_p=1`、温度 1），只换随机种子；任务提示明确写“同参考，只换种子”。
- **稳定性修复**：合成请求固定 `parallel_infer=false`。依据 GitHub issue #2658：有 prompt_text 时长句会被吞到 2–3 秒，关闭并行推理后恢复。
- **训练默认**：GPT 轮数从 8 对齐到官方 v4 WebUI 默认 15（SoVITS 2、LoRA 32）；8 轮在短素材上更容易吞字、语气发平。已有模型不自动重训，用户下次训练才使用新默认。
- **引导**：快速制作和高级编辑都加了“声音不满意？按这个顺序排查”清单：干净参考（微调约 1 分钟）、逐字一致的参考文字、先补素材再加轮数、短句/换种子、换 3–10 秒目标情绪参考、噪声音源先降噪或改 v2。
- **不改的边界**：仍保留 1–4 版手动选择、严格截断保护、去重合成和快速包流程；不自动替用户重训已有音色；不把游戏音频/听写缓存打进 exe。
- **依据**：官方 README/WebUI 默认、issues #2658 / #1644 / #636，以及 WT Live 语音包作者对素材质量的说明。详见 `docs/RESEARCH.md` 第 21 节。

## 26. M4.2 训练进度必须跨页面可见（2026-10-24）

- **问题**：训练只在自己的卡片里显示进度条，玩家切到工作台/素材页后看不到任务是否还在跑；GPT 训练阶段只显示原始日志，难以判断第几轮。
- **方案**：新增全局“任务进度”浮窗，轮询 `/api/jobs/current`，显示类型、阶段、百分比、已用时间、查看/取消；训练、合成、构建、目录、解包共用。
- **为什么不让每个页面各自轮询**：任务管理器已经是单任务模型，全局浮窗只加一处轮询，避免各页重复计时器和状态漂移；页面内进度条仍保留，用于当前上下文。
- **训练日志**：`_run`/`_run_env` 解析 `Epoch: N`，消息改为“第 N/总轮数”，百分比按轮数推进；预处理阶段继续显示原始步骤行。
- **边界**：浮窗只显示活动任务，结束后隐藏；完成提示仍由各页面处理，避免双重 toast。轮询 2 秒，隐藏标签页会被浏览器节流，恢复可见后下一轮补上。

## 27. 真实游戏台词 A/B 与 15 轮默认的边界（2026-10-24）

- **A/B 方法**：用 6 条真实游戏台词、同一参考/文本/种子、关闭并行推理，比较 8 轮和 15 轮；官方中文原音作对照。产物在 `D:\WTVoiceForge\质量对比_2026-10-24\`。
- **结果**：15 轮并非全面更好。字面 ASR 平均 8 轮 79.5%、15 轮 77.6%；15 轮修好一条短句，但另两条短句更差，长句基本一致。说明轮数不是主要矛盾。
- **决策**：代码默认仍保留官方 15 轮（新项目按官方默认），但不把“加轮数”作为解决不满意的推荐手段；原 8 轮项目和新的 15 轮项目都保留，用户可用真实台词试听后再选。提示文案明确写“短句上 8/15 轮可能各有胜负”。
- **边界**：ASR 只能发现吞字/重复，不能评价音色、情绪和电流声；最终仍需人耳和游戏内实听。

## 28. M4.3 快速制作里的“听—改—重生成”闭环（2026-10-24）

- **用户问题**：生成的语句散在列表里，无法连续听；也没有一键把已生成语音排起来、带中文、改词重生成的地方。
- **方案**：在快速制作第 4 步加试听台和单句重生成。播放队列使用项目台词顺序，只取有音频且非 non_voice 的行；播放时高亮当前卡片并显示用途 + 中文文本。
- **不先打包也能听**：`/api/voice/synthesize` 支持 `lines=[]` + `force=false` + `dedupe=true`，只补缺失；新增“只生成语音（先试听）”按钮复用这条接口，不触发 FMOD 构建。
- **改词重生成**：保存文本走原 `/api/voice/line/update`，后端会清空旧音频/takes；前端立即把行标成“未生成”，单句按钮走 `/api/voice/synthesize` 的 `lines=[id]` + `force=true`，完成后自动播放。
- **构建去重**：`generate()` 先算 `needsSynthesis`，没有待生成行时跳过 synthesize 直接 build；按钮文案显示待生成句数。这样“先试听再打包”不会因为“没有需要合成的台词”失败。
- **边界**：一键试听只播放已生成行，不自动补合成；非语音/提示音不参与；改词会使旧导出失效，必须重新构建。跨页面进度仍由 M4.2 的任务浮窗显示。

## 29. M5.0 用动态 AudioTable 打通游戏里的全部空战/陆战语音表（2026-10-24）

- **动机**：玩家可能开了全系，只做德/苏/英/美不够。游戏 `sound/` 有 61 张乘员表、33 个语言代码，而官方 FMOD 工程只提供 14 张 AudioTable。之前遇到没有元数据的表只能报错或退回中文表，无法真正替换。
- **决策**：不修改官方工程，也不要求用户等官方更新；在每次构建用的临时工程副本里，为缺失的表动态补 Bank + AudioTable。原音直接从游戏 bank 解出（vgmstream），再交给 FMOD CLI 重新构建。
- **目录设计**：动态原音放 `Assets/dialogs_dynamic/<bank>/<stream_index>/<name>.wav`。同名流可能有多个变体，按序号分子目录，避免覆盖；AudioTable 设 `sourceDirectory` 指向 bank 目录并开启 `includeSubDirectories`。
- **元数据生成**：新增 `app/dynamic_bank.py`。先找同名 Bank XML，有则补/更新 `audioTable` 关系；没有则生成确定性 UUID5 的 Bank 和根级 AudioTable。重复构建是幂等的，不产生重复对象。
- **构建**：`exporter.build()` 把 bank 分成“官方 AudioTable”和“动态表”。动态表要求已选择游戏目录；构建前解出整表（不只选中行），构建后包内 bank 保留全部流，manifest 记录 `dynamic_banks`。只替换选中流，其他流保持官方原音。
- **为什么整表解出**：FMOD AudioTable 构建时会按源目录生成完整表；只放选中的几条会让游戏其他事件失声。整表虽然慢（法语陆战 1308 条流），但行为可预测，且与官方 AudioTable 的构建方式一致。
- **变体处理**：`game_rows()` 按流名分组并保留全部 `game_index`。快速制作的每句台词绑定所有变体；中文模式合成一次后复制给同组所有变体，原语言模式同样用同一段换声音频覆盖所有变体。实测法语的 `artillery_1/10/2` 两组变体在成品 bank 中哈希一致。
- **国家与语言**：`quickpack.NATIONS` 扩到 10 个科技树；`ground_sm_*` 只在游戏里存在时加入。另提供“全部语音表”，直接列游戏里的 54 张空战/陆战表（17 通用 + 37 陆战，含 6 张补充），不把 33 个语言代码硬编码成国家。
- **实测边界**：法语陆战 654 个流名 / 1308 条变体，构建后仍 1308 条；3 句换声后 1↔927、421↔928、532↔929 哈希分别一致。游戏内实际加载仍未验证；海军暂不进入。

## 30. M5.0 原语言换声：用 RVC 保留语言，只换音色（2026-10-24）

- **需求**：有些玩家不想把语音包翻译成中文，只想用自己的声线替换原配音，同时保留原语言、语气和口音。
- **为什么不用 GPT-SoVITS**：GPT-SoVITS 是文本到语音，重读原语言需要逐句转写 33 种语言并准备多语言参考，成本和错误率都不可控；RVC 是音色转换，输入就是游戏原音，天然保留语言/语气，也不需要翻译。
- **引擎选择**：用官方 RVC 整合包（NVIDIA / RTX 50 / AMD DirectML），在自带 Python 3.9 环境里跑 v2 32k。训练复用项目已有的参考音频或 GPT 训练切片，不要求用户另备数据集；推理固定 `vc_single(sid=0, ...)`，RMVPE 音高、index_rate 0.75、protect 0.33、rms_mix_rate 1.0。
- **桥接**：宿主应用不安装 torch，也不 import RVC；通过 `app/engines/rvc_bridge/train_bridge.py` / `infer_bridge.py` 子进程执行，JSON 行输出阶段/进度/错误，宿主解析后写任务进度并支持取消（杀进程树）。这样 PyInstaller 单文件不会把 10GB 运行时打进去。
- **项目复用**：原语言包仍由“训练音色项目”克隆而来，沿用参考音频、台词用途和 RVC 模型；`quick.mode=original` 是唯一开关。准备阶段不跑听写/翻译，只补每句用途说明。
- **音频流**：`original.convert_project()` 为每句取主变体：官方表直接读 kit `Assets`，动态表从游戏 bank 解流。换声结果写回 `audio/<line_id>.wav`，构建映射会把同名的其余变体也指向这段音频；失败行保留原音，不阻断整包。
- **UI**：第 3 步选择“原语言换声”后显示 RVC 运行时状态/安装/训练；未训练模型时禁止准备。第 4 步隐藏中文文本框，保留“试听换声/试听原音”，构建按钮显示“批量换声并打包”或“直接构建原语言包”。
- **实测**：官方整合包训练 3 段 / 1 epoch 59 秒成功；推理修复说话人 ID 后，法语 3 句换声 → 写回 → 动态表构建全链路通过，输出 32 kHz 单声道、非静音；另跑通 3 句批量换声 + 整表 1308 条构建。
- **边界与诚实说明**：RVC 不保证消除原说话人的口音，跨语言只迁移音色；低码率游戏原音会放大齿音；训练素材仍建议 1 分钟以上。真实游戏内加载/实听未完成。

## 31. M5.1 座舱 VWS 走事件 bank 替换，不补 AudioTable（2026-10-24）

- **为什么不用动态 AudioTable**：`aircraft_gui` 在官方工程里已经是普通事件 bank，游戏通过事件播放 VWS；补 AudioTable 只能多打包一份同名流，不能保证游戏事件会读它。社区标准做法也是替换 `Assets/vws` 后重建 `aircraft_gui`。

- **中文台词来源**：优先用官方 xiao906 中文 VWS 原音听写并人工校正；xiao906 没有覆盖的告警按事件名语义补短句。内置文本只随应用分发手工整理结果，不分发游戏原音。
- **事件长度**：官方事件 XML 的 `SingleSound.length` 是固定值，直接换长中文会被截断。构建前恢复官方事件 XML，构建时按新 WAV 时长重写；不修改官方工程，也不改游戏目录。
- **工程版本差异**：官方工程比当前游戏少 6 条新增音效（热诱循环、UI 弹药等）。不静默假装保留：座舱清单逐条列出，构建以工程版本为准；击杀提示音 `ui_kill_assist` 已由 0.8.2 从游戏原音补回。
- **边界**：完整 324 条游戏流的游戏内加载/实听仍未验证；补回 `enemy_kill_assist` 后为 318 条，仍比游戏少 6 条。

## 36. 0.7.4 重复启动不再堆浏览器标签（2026-10-24）

- **问题**：启动器每次发现已有工作台都会调用默认浏览器的 `open(url)`；Edge 把每次调用当成一个新标签页，反复双击或自动化测试后会积累同一地址的多个标签。
- **方案**：工作台改用 Edge 应用窗口模式（`msedge --app=<url>`，无地址栏、无标签页）。再次启动时先按页面标题里的“ · 战雷声匠”枚举窗口并 `SetForegroundWindow`，找到就只聚焦，不再新开。
- **兜底**：服务端 `/api/health` 增加 `page_active`，由页面轮询/接口请求刷新（健康探测本身不计）。已有页面开在普通浏览器里、但窗口标题不是当前标签时，只退出不新开；页面关闭约 90 秒后才允许重新打开。没有 Edge 时回退默认浏览器。
- **边界**：新方案无法自动关闭用户之前已经打开的重复标签，需要手动关一次；之后不会继续增加。窗口标题聚焦依赖页面标题保留“ · 战雷声匠”后缀。

## 37. 0.8.0 改用内嵌 WebView2，不再开浏览器（2026-10-24）

- **问题**：0.7.4 虽然用 Edge 应用窗口避免了标签页，但本质仍是外部浏览器进程：玩家看到的是 Edge 窗口，不是软件自己的面板；安装包/卸载和窗口生命周期也不好统一。
- **方案**：引入 `pywebview 6.2.1` + `pythonnet`，在启动器进程里起本地 HTTP 服务，再创建 WebView2 原生窗口指向该服务。移除 Tk 启动器与 Edge 启动代码，双击后只有一个软件窗口；窗口关闭即停止服务。
- **兼容**：窗口使用独立缓存目录 `data/webview`，`private_mode=False` 保留 localStorage。启动前检查 WebView2 Runtime；缺失时弹窗并给出微软官方下载页，不退回 IE/MSHTML。重复双击按进程与标题聚焦已有窗口；页面开在普通浏览器时由 `page_active` 阻止重复开窗。
- **下载**：沿用 `app/components.py` 的官方/镜像下载与 SHA-256 校验，补前端进度（字节、速度、ETA、校验/解压阶段）和取消按钮；不改变下载源与完整性校验。
- **边界**：安装包与卸载程序仍待做；当前是绿色版。WebView2 依赖系统组件，未塞进 exe。

> 注：0.8.0 已将 Edge 应用窗口替换为内嵌 WebView2 本地窗口，见 #37；#36 的窗口形式已不再使用。

## 45. 0.9.1 换成 Field Manual 暖纸主题（2026-10-24）

- **问题**：0.9.0 的深色金属和琥珀色发光对用户来说“太张扬”，整体仍像网页模板；图标是六边形声波，和战雷、无线电、语音包的联系不够直接。软件要发给社区下载，界面需要更像一个真正的本地制作工具。

## 46. 0.9.2 修正任务浮层与击杀“叮”声映射（2026-10-25）

- **问题**：0.9.1 的暖纸主题只覆盖了任务浮层的进度条，卡片背景和 `.btn.ghost` 仍沿用深色主题，导致正文和按钮在深底上发灰；击杀音效则把 2026-06 新增的助攻提示 `enemy_kill_assist` 当成了空战击落的“叮”声。
